# 数据层双域映射走查（任务 2 验收项）

目的：验证 `src/data/types.ts` 的接口不贴合单一演示域（渠道投放），换一个业务域（电商经营）映射时不需改类型。红队报告 KA3 的缓解记录。走查时间：2026-09-25。

## 走查方式

把"电商经营周会决策"的假想数据逐字段映射到现有类型，检查是否有承载不了的信息形态。

## 映射结果

| 类型 | 渠道投放域（现有演示数据） | 电商经营域（假想走查） | 承载结论 |
| --- | --- | --- | --- |
| `MetricDef` | ROI / CTR / 转化率（x、percent） | GMV（currency）、退货率（percent）、客单价（currency） | ✅ format 四档够用 |
| `MetricSeries` | 14 天日序列 + 止损线/对比基线 | 周序列 + 目标线（如双周目标 GMV） | ✅ 基准线三分类（threshold/target/comparison）覆盖 |
| `Conclusion` | 「ROI 0.72 连续 3 日低于止损线」 | 「华南仓发货时效 48h 达成率 71%，低于承诺 90%」 | ✅ 严重度/标题/摘要/窗口结构域无关 |
| `DerivationStep` | 检测→归因→规则匹配→建议 | 检测（时效滑坡）→归因（暴雨压单）→规则（时效承诺缺口）→建议（临时切仓） | ✅ 四类步骤域无关 |
| `BreakdownRow` | 广告组贡献 ROI 偏离 | 仓库/品类贡献时效缺口 | ✅ dimension + contribution（±）语义域无关 |
| `SuggestedAction` | 暂停计划/追加预算 | 临时切仓/加派拣货班次 | ✅ |

## 走查结论

**通过**。类型中唯一隐含域假设的是 `BreakdownRow.contribution` 的量纲随指标变化（倍数/pt），这是"归因明细属于结论"这一结构的自然结果，走查未发现需要改类型的场景。

后续接真实数据源时（M2 前置门：真实数据源样本到位后），需再做一次同格式走查——本记录只证明接口对两个假想域的泛化性，不能替代真实数据的走查。
