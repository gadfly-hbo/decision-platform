## M3 三大件

### 1. 行动闭环（持久化 + 跨周追踪）

- 现状：行动状态（待定/采纳/驳回）是前端内存态，刷新即失（M1 有意决策：不持久化）。
- M3：后端 JSON 文件持久化（`data/actions.json`——量小、无并发诉求，不引数据库）；状态机扩展为 **待定 → 采纳 → 已执行（含执行备注）**，驳回保留；API `GET/PUT /api/actions`。
- **跨周闭环**：新周报导入计算后，把上周「采纳/已执行」行动与本周结论对照展示（上周动作 → 本周该渠道/指标的变化），闭环的"复"落在看板上。
- 前端：结论卡与行动汇总区的状态来自后端；新增执行结果录入。

### 2. 告警推送

- 触发：检测到**新期次**周报且首次计算产出结论时，自动生成并推送一次本周决策摘要（幂等：记录已推期次，重复刷新不重推）；另提供手动「推送本周摘要」入口与「测试推送」。
- 摘要内容 = 结论先行（本周要拍板的 N 件事 + 关键数字），不是数据通报；数字同样满足自洽契约。
- 渠道：通用 webhook POST（飞书/钉钉/企业微信自定义机器人任一），配置在 `data/notify.json`（**加入 .gitignore，凭证不入库**）；无配置则跳过推送并记录日志。
- 不做：定时调度（launchd/cron 文档化建议即可）、邮件、短信、多渠道并发。

### 3. 多周趋势

- `data/raw/` 累积多份周报 → 解析全部历史 → 生成周度时序（整体 6 指标 + 结论涉及的渠道指标）填充 `DashboardData.series` → M1 折线图自动启用（每点 = 一周，x 轴 = 期次）。
- **降级策略**：历史 <2 期时无 series（维持现状：贡献条形图兜底），概览头提示「累积 ≥2 期周报后展示趋势」。
- 趋势**图表** only：本期不新增"连续 N 周"检测规则——阈值无数据可校准（M2 KA2 教训：规则参数必须用真实样本调过才上线），等 ≥4 期数据后再评估。

## 全局约束（延续）

- 数字自洽契约：推送摘要/趋势数字一律可由同屏/同期数据复算。
- 纯 TS 计算层；不引数据库、不做多用户权限、不做移动端（「给谁用」仍未决，单机小团队假设延续）。
- Xanthil 视觉基线；测试缝延续（数据获取边界 + 纯函数 + echarts mock）。
- 双机同步：凭证文件（notify.json）与行动记录（actions.json）不随 git 走时的行为要文档化（MacBook 需自配凭证；行动记录双机各自独立——已知限制，明示）。
