# 提案：decision-platform M7 — 会议汇报模式（Presentation Mode）

日期：2026-10-13。来源：用户场景反馈 + 方向确认稿回复（本会话）。

## 用户原话（决策锚点）

> 这个看板的使用场景会有一个是会议场景，所以决策看板需要有一个很好的视觉呈现能力

方向确认稿回复：**按推荐**——即四项推荐全部采纳：

1. **形态 = 独立汇报模式**（一键切换的汇报流视图，工作台不动）
2. **会中操作 = 保留采纳/驳回**（驳回弹窗大字号版；操作后自动进下一条）
3. **配色 = 亮色放大版**（沿用 Xanthil 亮色基线；不做暗色版）
4. **排序 = 默认「待拍板」（suggested）按 优先级 > 置信度**；可切「全部」

## 已确认的决策（约束）

- 纯前端特性：数据全来自现有 BoardView 与既有行动项端点，无后端 schema/API 变更。
- 汇总页：项目名 + 大字统计（报告 N · 建议 X · 高优 Y · 已采纳 Z）+ 证据分布条（纯 CSS 四色）+ 高优/数据支撑一行式议程清单。
- 逐项页：单条一屏、大字号（3 米可读）、固定信息结构（标题 → 证据四色标 + 置信度大数字 → 报告原文引用块 → 预期效果 → 优先级/投入徽标）、页码指示（3/8）、来源报告名、键盘 ←/→/Home/End 推进。
- 「汇报模式」按钮（概览头）+ 快捷键进入；Esc 退出回工作台；焦点管理。
- 操作同库同留痕（与飞书卡片先到先得语义共存）；「全部」模式可复盘已决项（含留痕展示）。
- 视觉：层级靠字号/间距/四色证据标，不加装饰性大色块；遵循全局 UI 基线（亮色、克制、结论先行、证据可展开）。

## 被否决

- 暗色投影版（决策 3）、仅增强工作台密度（决策 1）、纯只读（决策 2）、重新引入 echarts（分布条用纯 CSS）。

## 未决（GRILL）

- 快捷键具体键位与浏览器全屏（Fullscreen API）是否联动。
- 「全部」模式内已决项的呈现（留痕行如何排布）。
- 驳回弹窗在汇报模式的大字号规格与焦点返回（Esc 语义冲突：Esc 退弹窗 vs 退模式）。
- 空态（无待拍板项时进入汇报模式）。
