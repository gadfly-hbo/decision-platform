## 1. 窗口与布局骨架（三栏工作台 shell；左栏语义 v5 = 项目导航）

```
┌──────────────┬─────────────────────────────────────────────┬────────────┐
│ S-L 项目导航   │ 主内容区（自适应宽，= 当前项目的看板）              │ S-R 运行详情 │
│ 固定 ~240px   │ ┌ S1 项目概览头：项目名(+purpose)·统计·通知chip   │ 可开关抽屉   │
│              │ │            ·[运行详情]开关（全局，G4'）      │ 默认收起    │
│ [＋ 新建项目]  │ │ S1b 报告区：[上传报告] + 项目内报告列表        │ ·模型链状态 │
│ ──────────── │ │   （状态四态 / 重试 / 重新生成两段式）         │ │  (主/备+密钥)│
│ 项目列表       │ │ S6 过滤器（报告维=项目内报告）+ [补充建议]      │ │ ·任务账本用量│
│ · 项目名      │ │ S2 行动项卡片流                               │ │  (全局账本) │
│ · 行动项{n}   │ │   卡内：S3 证据 / S4 任务 / S5 反馈 / S12 补填 │ │ ·抽取事件   │
│ · 最近活动    │ │ S11 驳回弹窗、S14 删除项目弹窗 = 仅有的两处弹层  │ │  时间线     │
│ · 当前项:编辑/×│ └ 全局保存失败 alert ────────────────────┘   │            │
│ (空态:尚无项目)│ 无项目时：主区 = 无项目空态引导卡（S8，G4'）        │            │
└──────────────┴─────────────────────────────────────────────┴────────────┘
```

- **左栏 S-L**：固定窄栏（~240px），项目导航（见 2.15，v5 替换 M5 的报告导航）。
- **主内容区**：**当前项目**的看板——S1 项目概览头 / S1b 上传报告 + 项目内报告列表 / S6 过滤器 / S2 卡片流（卡内 S3/S4/S5/S12）。宽度自适应（G14 沿用）。
- **右栏 S-R**：「运行详情」抽屉，默认收起，S1 右端开关钮（见 2.16）；**账本是全局的**，无项目空态下仍可打开（G4'）。
- **DOM/焦点顺序（G13 沿用）**：主内容在前、侧栏在后——DOM 顺序 = `<main>` → `<aside S-L>` → `<aside S-R>`，视觉左右由 grid 列位控制。无路由。
- **当前项目记忆（G7'，v5 新增）**：无路由不变；当前选中项目持久化在 `localStorage.dp.activeProjectId`，刷新/重启回到最后项目；项目被删后回退到列表首个项目，无项目则回无项目空态。此为状态记忆，非路由。
- **窄屏约定（<1080px）**：三栏解除为单列，DOM 顺序即视觉顺序（主区最前）；S-L 折为主区上方横向条（可横向滚动），S-R 折为主区下方面板。
- **弹层条款（v5 修订）**：弹层共**两处**——S11 驳回理由弹窗（G10）与 S14 删除项目确认弹窗（用户确认「硬删+确认弹窗」），均复用原生 `<dialog>` + `--scrim` 基线与同一焦点管理约定。S-R 抽屉不是弹层/模态（无遮罩、不圈焦点）；新建/编辑项目、补充建议、任务编辑、补填理由等一切表单均为 inline。

### 2.1 S1 项目概览头（v5）

- 位于主区顶部（统计与通知 chip 不进侧栏，G14 沿用）；显示**当前项目**。
- 标题 = 项目名（`.page-title`）；副题（`.overview-lede`）= 项目 purpose，purpose 为空时显示固定副题 `报告驱动的行动闭环`。
- 元信息行（`.overview-meta`）：`共 {N} 份报告 · 建议 {a} · 已采纳 {b} · 已驳回 {c} · 人工 {n}`（`人工 {n}` = 项目内人工补充项计数，恒显，v4 勘误），后接通知 chip。**不再显示**「最新报告 · 导入时间」（报告时间在 S1b 列表）与任何演示 chip。
- 通知 chip 四态（沿用 `.notify-chip`；数据源 = BoardView.notify 的 `configured` / `imConfigured` / `lastPushedReport`，推送集合来自 notify-state）：
  1. 飞书已配置且已推送（`imConfigured` 且 `lastPushedReport` 非空）→ ok 色 `已推送 · {项目名}/{报告名}`（G5' 短形态）
  2. 飞书已配置未推送（`imConfigured` 且无 `lastPushedReport`）→ warn 色 `已配置 · 未推送`
  3. 飞书未配置、webhook 已配置（文本摘要降级）→ warn 色 `未配置飞书 · 文本摘要推送`
  4. 均未配置 → warn 色 `推送未配置`
- 行右端「运行详情」开关钮（plain 样式）：`aria-expanded={抽屉开}` + `aria-controls` 指向 S-R；关闭后焦点回开关钮。无项目空态下该开关钮保留在引导卡头部（G4'：账本全局）。
- **不出现**校准/teach/学习类文案（G12 无用户可见界面，负面用例 7）；**不出现**演示类文案（负面用例 2）。

### 2.2 S1b 报告区（v5：上传报告 + 项目内报告列表）

- **区头**：标题「报告」+ 右侧「上传报告」主按钮（accent 主操作样式）→ 触发隐藏 `<input type="file" accept=".md,.txt" multiple>`；上传中按钮 disabled + 「上传中」指示。
- **上传语义**：
  - 上传即注册 pending 并**立即异步触发抽取**（不阻塞上传响应、不需要手动再点，M6-US3）；多文件逐份处理、单份失败不影响其余（G2'），失败项以独立列表项呈现。
  - 校验失败（>2MB / 非 .md/.txt / 非 UTF-8 可读）→ 该项 `上传失败：{原因}`（fail 色），原因文案：`文件超过 2MB` / `仅支持 .md/.txt 文件`（G2'）。
  - **同名上传 = 覆盖文件并按 force 语义重抽**（G1'）：不弹「重名确认」，该报告项原地进入 `抽取中`；仍处「建议」的抽取项删除重建、已决/含任务项保留（同 G3 保护）。
- **报告列表**（按导入时间倒序，G1 沿用）：每项 = 文件名 + 导入时间（MM-DD HH:mm）+ 状态 chip + 操作：
  - `待抽取`（queue 色）+「抽取」按钮（异步触发失败的兜底手动入口）
  - `抽取中`（queue 色 + 旋转，见 S10）
  - `已抽取`（ok 色）+「重新生成」两段式按钮：首次点击变为「确认重新生成」，提示文案 `重新生成将删除该报告中仍处「建议」状态的行动项；已采纳/已驳回/含任务的行动项保留`，再点执行 `force:true`，失焦或 3 秒未点自动还原（G3 沿用；M5 文案「重新抽取」废止，统一为「重新生成」）
  - `抽取失败`（fail 色）+ 原因摘要（如 `模型调用超时（120s）`）+「重试」按钮
- 每份报告每轮只推送一次（幂等键 = `projectId:slug`）；已推送不因刷新重复推（状态在 S1 通知 chip 汇总）。
- 重新生成的删除重建仅作用于抽取项；人工补充项（manual 直挂 project_id）不受影响。
- 报告文件不在 UI 提供单独删除入口（报告随项目硬删，proposal 决策 6）。

### 2.3 S2 行动项卡片（完整规格，v4 勘误已并入）

- 沿用卡片骨架（`.conclusion-card` 同款 surface/border/`--r-base`/`--shadow-card`，类名 `.action-card`）；整卡头为 `<button aria-expanded>`，chevron `▸/▾`。
- 卡头内容：
  - chip 行：状态 chip（建议=queue 色 / 已采纳=ok 色 / 已驳回=中性灰，对齐 `st-pending/st-accepted/st-rejected` 按下配色）、证据等级 chip（四级色标，见第 6 节）、优先级 chip（高=fail 色 / 中=warn 色 / 低=queue 色，对齐 `sev-*` chip）、effort/scene/lifecycle 值 chip（中性，值 = 模型枚举输出原样中文，UI 不翻译不改写；枚举集合由实现阶段 validator 定义）、所属报告 chip（**当前项目内**报告文件名去扩展名；人工项 = 「人工补充」）。
  - 标题（`.card-title`）+ rationale（`.conclusion-summary` 同款副文本，无前置标签）。
  - 右侧 meta：抽取项 `置信度 {0–100 整数}%`；**人工项**显示中性徽标「人工」（替代置信度数值，不参与派生公式）。置信度必须由证据派生，禁止呈现为模型自评。
- 操作区（卡头下方常显，不依赖展开）：按钮组「采纳」「驳回」（`aria-pressed` 单选语义，suggested 态两者均未按下）；已决后显示留痕 `decidedBy · MM-DD HH:mm · 渠道`，渠道 ∈ {看板, 飞书}（沿用 `.decided-meta`）。
- **改判单向（v4 勘误）**：`suggested → adopted / dismissed`（驳回经 S11 弹窗）与 `adopted → dismissed`（仍经弹窗）允许；**`dismissed → adopted` 不允许**——已驳回项不显示「采纳」钮（仅「驳回」按下态 + 留痕），恢复路径 = 该报告重新生成或人工补充新建议。
- **驳回交互（G10）**：点「驳回」不直接落库，先开 S11 弹窗，理由确认后才 `dismissed`；改判为驳回同样经弹窗；取消/Esc = 无变更。
- **已驳回卡展开**：证据展开区首块「驳回理由」（见 2.13）；看板渠道驳回显示已填理由只读文本；飞书渠道驳回显示默认值 `卡片驳回（未填理由）` + 补填入口（S12）。
- 不提供删除行动项入口（`DELETE /api/actions/:id` 不设 UI 按钮，保护决策留痕）。

### 2.4 S3 证据展开区（完整规格）

抽取项卡头展开后（`.evidence` 分区，沿用 `.evidence-block` 虚线分区），自上而下：

1. **事实**（facts）：每条 = 事实等级 chip（四级色标）+ 报告原文引用块（`quote-block`：左侧 3px 等级色边 + `--soft` 底，原文逐字，不加引号装饰、不转写）+ 该事实一句话说明。
2. **推导过程**（reasoning）：正文段落。
3. **预期效果**（expectedImpact）：正文段落。
4. **置信度说明**：`置信度由证据派生（证据等级与原文引用决定），非模型自评。`
5. **警示行**（钉死逐字，不可省略）：`证据等级由提取模型自评，未做真实数据重验证`
- facts 为空（validator：无 facts 置信度封顶 0.5）时显示：`未引用报告事实（置信度已按无事实封顶 0.5）`（`.empty-lite`）。
- **人工项变体（G11）**：无「事实」块（`.empty-lite`：`人工补充建议，未引用报告事实`）；「推导过程」= 表单「依据」原文；无「预期效果」块；第 4/5 条替换为一行说明 `人工补充建议：不参与置信度派生，证据等级固定「经验假设」。`（人工项无模型自评环节，原警示行对其不成立）。
- **禁止**出现：核心指标图、归因明细表、贡献图、任何 ECharts 图表。

### 2.5 S4 任务列表与编辑（完整规格，v4 勘误已并入）

- 仅 `status=adopted` 行动项卡内展示（人工项采纳后同权）；区块标题「任务」。
- 任务行：状态三钮（待办/进行/完成，`aria-pressed` 单选，配色：待办=queue、进行=warn、完成=ok）+ **标题**（主文本，必填字段）+ 副行 meta `负责人 {owner} · 截止 {YYYY-MM-DD} · 优先级 {高|中|低} · 备注 {note}`（未填项省略）+「编辑」按钮（展开行内表单，与新增表单同构、预填现值，非弹层）。
- 新增任务表单（v4 勘误）：**标题\***（文本，必填）、负责人（可选文本）、截止日（可选 date）、优先级（可选 select 高/中/低，默认中）、备注（可选文本）；按钮「添加任务」「取消」；校验失败字段下 error `请填写标题`。
- 任务无删除按钮（API 未提供 DELETE /api/tasks/:id）；无任务时 `.empty-lite`：`暂无任务，添加第一个执行任务`。

### 2.6 S5 反馈回录表单（完整规格，v4 勘误已并入）

- 每任务一条反馈（一任务一条，API upsert）：
  - **未回录** → 表单：已执行（checkbox，默认勾选）、结果\*（textarea）、指标变化（文本，placeholder 例 `复购率 +2.3pp`）、复盘（textarea）、评分\*（radio 1–5，组提示 `5=显著正向效果 · 3=无明显变化 · 1=显著负向`，G4）；按钮「提交反馈」。
  - **已回录** → 只读反馈块（`.action-review` 同款虚线区）：`已执行|未执行 · 评分 {n}/5` + 结果/指标变化/复盘各行 + 「更新反馈」按钮——点击展开同构表单（预填现值）走同端点覆盖保存，保存后回到只读。
- 提交成功后表单原地替换为只读块。

### 2.7 S7 演示态（**v5 移除**）

v1–v4 的演示态（「演示数据」chip、说明条 `当前为演示数据：将分析报告（.md/.txt）放入 data/raw/ 后自动抽取真实行动项。`、固定 3 条演示行动项、演示不落库约定）随 M6 项目化**整节退役**（PRD 前端节 + G4'）：demo 数据与相关测试删除，组件不保留。原触发条件「无报告」由两类真实态替代：**无项目** → S8-① 无项目空态引导卡；**有项目有报告但无密钥** → S9 无密钥错误条。任何「示例/演示」形态在全站禁现（负面用例 2）。

### 2.8 S8 空态（v5 扩充为三种）

1. **无项目空态**（项目列表为空，G4'）：主区 `.empty` 引导卡——标题 `尚无项目`，一句话说明 `新建一个项目，在项目内上传报告即可生成看板。`，主按钮「＋ 新建项目」点击在卡内展开同款 inline 新建表单（见 2.15）；S-L 列表区同步显示空态文案；「运行详情」开关钮保留在引导卡头部（G4'）。
2. **报告空态**（当前项目有报告、抽取成功、0 行动项；抽取返回空数组是合法结果）：`.empty` 卡，标题 `该报告未抽取到行动项`，提示 `报告已解析完成，但未包含可执行建议；可尝试重新生成或检查报告内容。`
3. **过滤空态**：列表区 `.empty-lite`：`该过滤条件下暂无行动项`。

### 2.11 S-EXT 飞书审批卡片（外部表面，内容契约）

### 2.12 S11 驳回理由弹窗（G10，弹层之一）

- **触发**：看板点「驳回」（首次驳回或 adopted→dismissed 改判）。
- **实现约定**：原生 `<dialog>` + `showModal()`——原生 Esc 关闭、焦点圈定、`aria-modal` 免手写。视觉 = 平面卡片（`--surface` + `--border` + `--r-base` + `--shadow-card`）+ 遮罩 `--scrim`；宽 `min(420px, 90vw)`。
- **内容**：标题「驳回行动项」+ 所驳回行动项标题（只读引用，`.card-summary`）；`驳回理由 *` textarea + helper `至少 2 个字`；按钮 [确认驳回]（主操作样式）[取消]（普通样式）。
- **校验**：必填 ≥2 字；不足时弹窗内 error（`role="alert"`，fail 色）：`请填写驳回理由（至少 2 个字）`，焦点保持 textarea。
- **焦点管理**：打开 → 聚焦 textarea；确认/取消/Esc 关闭 → 焦点回到触发它的「驳回」钮。提交中两钮 disabled。
- **落库**：确认后 `status=dismissed` + `dismissedReason` + 驳回时间/渠道（看板）；取消 = 无变更。

### 2.13 S12 补填理由（inline，G10）

- **可见条件**：`status=dismissed` 的行动项，证据展开区首块「驳回理由」：
  - 飞书渠道驳回（理由为默认值）→ 显示 `卡片驳回（未填理由）` + 补填输入（label「补填理由」，单行，≥2 字同校验）+ [保存]；保存成功后原地替换为只读理由文本。
  - 看板渠道驳回 → 显示已填理由只读文本，不再提供覆盖入口（理由是已沉淀的决策资产；「补充后覆盖」语义限定卡片渠道）。
- 保存失败走 S9 保存失败 alert；飞书卡片本身无输入框。

### 2.14 S13 补充建议表单与人工补充项（G11）

- **入口**：过滤器区右上「补充建议」主按钮（accent 主操作样式，S6 内唯一主按钮）。
- **表单（区内 inline，非弹窗）**：标题\*（文本）、依据\*（textarea）、场景/周期/优先级/投入（各一枚可选 select，首项「不填」，值集合 = 抽取枚举同一套，由 validator 定义）；按钮 [提交][取消]。
- **提交后**：创建 `sourceKind=manual` 行动项（**直挂当前项目**，reportId 空），状态=**建议**（仍需采纳确认）；归入过滤器「报告」维「人工补充」分组；证据等级固定「经验假设」（灰）；卡头 meta 显示中性徽标「人工」替代置信度；报告 chip 为「人工补充」。
- **人工项证据区**：见 2.4 人工项变体。
- 人工项与抽取项同权走 确认 → 任务 → 反馈 闭环；不受报告重新生成影响（2.2）。
- 表单校验失败（标题/依据为空）：字段下 error `请填写{标题|依据}`；提交失败走 S9。

### 2.15 S-L 左栏项目导航（v5，替换 M5 报告导航）

- **结构**（固定窄栏 ~240px，`<nav aria-label="项目导航">`）：
  1. 顶部「＋ 新建项目」主按钮 → 展开 inline 表单：`名称 *`（文本必填）+ `目的`（可选文本，placeholder 例 `这个看板跟踪什么业务`）+ [创建][取消]；Enter 提交、Esc/取消收起；创建成功后切换为新项目并收起表单。校验失败 error `请填写名称`。
  2. 项目列表：每项 = 项目名（超长截断省略）+ `行动项 {n}` 计数 chip（中性）+ 最近活动时间（MM-DD HH:mm）；**当前项目高亮**（accent-soft 选中态，`aria-pressed`）。
  3. 当前项目项附操作：`编辑`（aria-label `编辑 {项目名}`）→ 展开 inline 表单（同新建表单构，预填名称/purpose，[保存][取消]，PATCH 语义）；`×`（aria-label `删除 {项目名}`）→ 打开 S14 删除确认弹窗。非当前项目项仅 `×`。
- **点击行为**：点项目项 = **切换当前项目**（主区整体换数据源：S1/S1b/S6/S2 全部切换；非路由），并写入 `localStorage.dp.activeProjectId`（G7'）；删除后回退列表首个项目或无项目空态。
- **删除 = 硬删**：确认后事务级联清数据 + 删项目目录（proposal 决策 6）；无归档、无软删路径。
- **空态**（无任何项目）：列表区 `尚无项目——新建一个开始。`，与主区引导卡（S8-①）并存。
- 可访问性：nav 项为 `<button aria-pressed>`；`×`/`编辑` 为独立小钮（不触发项目切换）；窄屏折横向条后同样可 Tab 触达。
- 信息组织参考 report-factory wb-sidebar（新建 inline 表单/列表/删除 ×/活动时间），样式一律 Xanthil 基线（负面用例 9）。

### 2.16 S-R 右栏「运行详情」抽屉

- **开关**：S1 概览头右端「运行详情」按钮（`aria-expanded` + `aria-controls`）；**默认收起**；收起时主区完全不受影响；无项目空态下开关钮在引导卡头部，抽屉仍可打开（G4'）。
- **非模态**：无遮罩、不圈焦点（区别于弹窗）；关闭（开关钮或抽屉头部「关闭」钮）后焦点回开关钮；`<aside aria-label="运行详情">`，头部 = 标题「运行详情」+「关闭」按钮。
- **内容三块**（数据来自 `/api/health` 模型链信息、BudgetStore 快照、审计/日志投影）：
  1. **模型链状态**：主/备模型各一行（角色词 主/备 + 模型名）+ 密钥 chip（就绪=ok 色 / 未配置=fail 色）。
  2. **任务账本用量**（chips，**全局账本**、跨项目累计，G4'）：`模型调用 {n}` · `token 入 {n}` · `token 出 {n}` · `用时 {n}s`。
  3. **抽取事件时间线**：最新在前；每行 = 时间（HH:mm:ss）· 事件（抽取开始/抽取成功/抽取失败）· 报告名 ·（成功时行动项数 / 失败时原因行，fail 色）。
- **空时间线**：`暂无抽取事件——放入新报告后此处显示。`
- 密钥未配置时模型链行呈 fail chip，与 S9 无密钥错误条同源数据、不同呈现。

### 2.17 S14 删除项目确认弹窗（v5 新增，弹层之二）

- **触发**：点 S-L 项目项的 `×`。
- **实现**：复用 S11 基线——原生 `<dialog>` + `showModal()` + `--scrim`，宽 `min(420px, 90vw)`，平面卡片样式。
- **内容**：标题 `删除项目`；所删项目名（只读引用，`.card-summary`）；正文逐字 `项目及其报告文件将一并删除，不可恢复。`；按钮 [确认删除]（**fail 语义色**：`--fail-soft` 底 + `--fail-line` 边 + `--fail` 字——破坏性主操作，色+文字双通道）[取消]（普通样式）。
- **焦点管理**：打开 → 聚焦 [取消]（破坏性操作安全位，防回车误删）；确认/取消/Esc 关闭 → 焦点回触发的 `×` 钮。提交中两钮 disabled。
- **落库**：确认 → `DELETE /api/projects/:id`（硬删 + 目录清理）；取消 = 无变更。删除成功后按 G7' 回退（列表首个项目或无项目空态）。

## 3. Click paths

### 3.1 主成功路径（M6：新建项目 → 上传 → 闭环）

1. **新建项目**：S-L「＋ 新建项目」→ inline 表单（名称\*、目的可选）→「创建」→ 新项目成为当前项目（主区空看板 + 报告区引导上传）。（首启平行入口：无项目空态引导卡内同款表单。）
2. **上传报告**：S1b「上传报告」→ 选 1..n 个 .md/.txt → 逐份写入并**立即异步抽取**（列表项 上传中→待抽取→抽取中，aria-live）→ 抽取完成（已抽取）→ S2 出现新行动项（状态=建议）；抽取完成后按项目推送（【项目名】摘要，高优卡片逐条，US14/M6-US8）。
3. **看证据**：点卡头（或 Enter/Space）→ S3 展开：事实引用块（四级色标）→ 推导过程 → 预期效果 → 置信度说明 → 警示行 → 30 秒内判断（US2）。
4. **确认**：点「采纳」→ 「已采纳」（ok）+ 留痕 + 任务区出现。点「驳回」→ S11 弹窗填理由（≥2 字）→「确认驳回」→「已驳回」+ 理由与留痕沉淀。（平行路径：飞书卡片单键采纳/驳回 → 看板同步，渠道=飞书；卡片驳回理由为默认值，S12 补填。）
5. **拆任务**：已采纳卡内「添加任务」→ 标题\* + 负责人/截止日/优先级/备注 → 任务行出现（默认待办）；状态钮 待办→进行→完成（US9）。
6. **回录反馈**：任务下「提交反馈」→ 已执行/结果/指标变化/复盘/评分 → 只读反馈块（可「更新反馈」覆盖）（US10）。闭环完成。
7. （改判单向：adopted→dismissed 经弹窗；dismissed 不回采纳，恢复走重新生成或人工补充。）

### 3.2 次级结果路径

- **加载中**：任意写操作 disabled + 保存中指示；上传中/抽取中见 S1b/S10。
- **空结果**：项目无报告 → 报告区引导上传；报告抽取 0 条 → S8-②；过滤器无命中 → S8-③；无项目 → S8-①（不再是演示态，v5）。
- **部分结果**：多文件上传单份失败不影响其余（G2'，逐份结果项）；项目内一份报告失败可重试，其余照常。
- **同名上传**：直接覆盖 + force 重抽（G1'），不弹重名确认。

### 3.3 显式失败路径

- **上传失败**：`上传失败：{文件超过 2MB / 仅支持 .md/.txt 文件}`（列表项 fail）；重选文件即可，其余文件不受影响。
- **抽取失败重试**：`抽取失败：{原因}`（S-R 时间线同现失败行）→「重试」→ 抽取中 → 成功或再失败（保留重试，US16）。
- **重新生成（G3 沿用）**：已抽取报告 →「重新生成」→「确认重新生成」（两段式 + 删除范围提示）→ force 重抽：仍处「建议」的抽取项删除重建，已采纳/已驳回/含任务的保留；人工项不受影响。
- **保存失败**：任一写操作失败（含弹窗确认、补填、补充建议、任务/反馈、项目创建/编辑/删除）→ `role=alert`「保存失败，已恢复为服务器状态」→ 回滚可重试。
- **飞书不可用降级**：通知 chip `未配置飞书 · 文本摘要推送` / `推送未配置`；不阻塞闭环。

### 3.4 变更回灌路径（G10/G11）

- **看板驳回（带理由）**：点「驳回」→ S11 弹窗 → 填理由 →「确认驳回」→ dismissed + 理由留痕；「取消」/Esc 无变更。
- **飞书单键驳回 → 补填**：卡片点「驳回」→ 看板该卡 dismissed、理由 `卡片驳回（未填理由）` → 展开证据区 → S12 补填 → [保存] → 理由只读沉淀。
- **人工补充建议**：S6「补充建议」→ S13 表单 → 人工项出现在「人工补充」分组（状态=建议、「人工」徽标、经验假设）→ 走 3.1-4~6 同权闭环。
- G12 校准注入为后端 prompt 行为，**v5 起按项目过滤**（本项目驳回理由 + 人工补充，M6-US7），仍无用户可见路径（负面用例 7）。

### 3.5 工作台路径（v5：项目化）

- **切换项目**：点 S-L 项目项 → 主区整体切换为该项目看板 → `dp.activeProjectId` 记忆（G7'）；刷新/重启回到最后项目。
- **新建项目**：见 3.1-1；创建后立即切换。
- **删除项目**：点 `×` → S14 弹窗（聚焦取消）→「确认删除」→ 硬删（数据+文件目录）→ 回退列表首个项目或无项目空态；「取消」/Esc 无变更。
- **编辑项目**：当前项「编辑」→ inline 表单改名称/purpose → 保存（S1 标题/副题即时更新）。
- **运行详情**：点 S1「运行详情」→ S-R 展开（模型链/账本/时间线）→ 主区不受影响 → 「关闭」/开关钮收起、焦点回开关钮。

### 4.2 键盘与焦点顺序

- **DOM 顺序（G13 钉死）**：主内容在前、侧栏在后——`<main>`（S1 开关钮 → S1b 上传/报告操作钮 → S6 过滤器 + 补充建议 → 卡片流逐卡：卡头 → 采纳/驳回 → 展开区内 驳回理由/补填 → 任务/编辑 → 表单）→ `<aside S-L>`（新建按钮 → 项目项 → 当前项 编辑/×）→ `<aside S-R>`（关闭钮）。Tab 序即 DOM 序；视觉列位由 grid 控制。
- **弹窗焦点圈定**：S11 打开聚焦 textarea、关闭回驳回钮；S14 打开聚焦 [取消]、关闭回 `×` 钮——两处均原生 `showModal` 圈定，Tab 不越出。
- **S-R 非模态**：不圈焦点、无 Tab 陷阱。
- 全部交互件可 Tab 触达，禁用件 `disabled` 移出焦点；无正 tabindex、无其他焦点陷阱。
- 焦点环统一：`outline: var(--focus-ring); outline-offset: 2px`（3px 半透明橘，所有交互件 `:focus-visible`，含弹窗与抽屉内控件）。

### 4.3 可访问性约束

- 展开态 `aria-expanded` + `aria-controls`；抽取进度区 `aria-live="polite"` + `aria-busy`；错误 `role="alert"`（含弹窗校验 error）。
- 弹窗用原生 `<dialog>`（`aria-modal` 浏览器提供）；关闭后焦点归还触发钮；S14 破坏性确认聚焦安全位（取消）。
- 状态/等级均色 + 文字双通道（chip 内必有文字、状态点带文字）；语义色对（深字 + soft 底 + line 描边）保证对比度；正文 ≥ `--fs-small`。
- `lang="zh-CN"`；表单必填 `*` + label 标注（评分 radio 组 legend；弹窗理由关联 helper 与 error）。
- 上传 input 有可访问名称（触发按钮文本「上传报告」）；`×`/`编辑` 与项目切换钮分离（独立 focus target，Enter 不误触删除）。
- 窄屏 <1080px：侧栏折叠为横向条/下方面板，DOM 顺序不变（主内容最先），键盘与读屏顺序一致。

## 7. Negative cases（禁止清单）

1. **旧形态禁现**：结论卡、推导链路、核心指标图/贡献图（ECharts）、归因明细表、跨周对照/周趋势、期次与数据窗口文案——全部不出现。
2. **演示形态全站禁现（v5 修订）**：S7 退役后不得出现「演示数据/示例报告」chip、说明条、演示行动项或任何示例冒充；无项目首启 = 引导卡（G4'），无密钥 = S9 错误条；不得以任何演示态遮掩空态或故障。
3. **证据警示不可省（抽取项）**：抽取项证据区必须逐字呈现「证据等级由提取模型自评，未做真实数据重验证」；过滤器区同附。人工项以 2.4 变体说明行替代。
4. **弹层两处为限（v5 修订）**：仅 S11 驳回理由与 S14 删除项目确认两处弹窗（均用户明确要求的窗口/确认）；S-R 非模态；新建/编辑项目、上传、补充建议、任务编辑、补填理由一切 inline，不得再造第三处弹层/浮层；不发明 PRD 外界面（无 JuanerAI 入口占位、无项目归档/软删、无项目级审批人配置、无行动项删除钮、无路由）。
5. **置信度表述**：只能「由证据派生」口径与数值；人工项只显「人工」徽标，不得伪造百分比。
6. **quote 逐字**：引用块逐字呈现报告原文，不摘要、不转写、不加装饰引号。
7. **G12 校准注入无用户可见界面**：不产生任何界面/标签/状态/说明文案；「校准/teach/调优/学习」不入用户文案；v5 项目级过滤同样不可见。
8. **飞书卡片无输入框**：驳回单键直驳；理由输入只存在于看板（弹窗/补填）。
9. **布局纪律（v5 修订）**：左栏 = 项目导航，**不得出现全局报告列表**（跨项目报告聚合/全局目录扫描形态）；S-L 点击 = 切换当前项目（数据源切换），不是过滤器聚焦、不得做成路由页；S-R 收起不留残留；S1 统计/通知留主区；不照抄 reports-factory 样式/token。跨项目数据不串：S6 报告维仅含当前项目报告，卡片报告 chip 为项目内报告。
10. **上传纪律（v5 新增）**：上传仅 .md/.txt 多文件、单文件 ≤2MB（G2'）；同名 = 覆盖 + force 重抽（G1'），不得弹「重名确认」；单份失败不得阻断同批其余文件；报告删除只随项目硬删，无单报告删除钮。
