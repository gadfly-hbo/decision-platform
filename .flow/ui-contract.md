## 1. 窗口与布局骨架（v3：三栏工作台 shell，G13）

**v1/v2 的 `max-width 860px` 单列居中约定废止（G14）**，改为三栏自适应 shell：

```
┌────────────┬───────────────────────────────────────────┬────────────┐
│ S-L 报告导航 │ 主内容区（自适应宽）                          │ S-R 运行详情 │
│ 固定 ~240px │ ┌ S1 概览头（统计/通知 chip）……[运行详情]开关 ┐ │ 可开关抽屉   │
│            │ │ S1b 报告状态条（带 抽取/重试/重新抽取 钮）   │ │ 默认收起    │
│ ▸ 全部(默认) │ │ S6 过滤器 + [补充建议]                    │ │ ·模型链状态 │
│ ▸ 人工补充   │ │ S2 行动项卡片流                            │ │  (主/备+密钥)│
│ ────────── │ │   卡内：S3 证据 / S4 任务 / S5 反馈        │ │ ·任务账本用量│
│ 报告列表     │ │         / S12 补填理由                    │ │  (调用/token │
│ 名·时间·状态点│ │ S11 驳回弹窗 = 全站唯一弹层（G10）         │ │   /用时)    │
│ (无删除入口) │ └ 全局保存失败 alert ───────────────────┘   │ │ ·抽取事件   │
│            │                                             │ │  时间线     │
└────────────┴───────────────────────────────────────────┴────────────┘
```

- **左栏 S-L**：固定窄栏（~240px），报告导航（见 2.15）。
- **主内容区**：既定四区不变（S1 概览头 / S1b 报告状态条 / S6 过滤器 / S2 卡片流 + 卡内 S3/S4/S5/S12 + S11 弹窗）；宽度自适应。
- **右栏 S-R**：「运行详情」抽屉，默认收起，主区概览头（S1）右端开关按钮切换（见 2.16）。
- **DOM/焦点顺序（G13）**：主内容在前，侧栏在后——DOM 顺序 = `<main>` → `<aside S-L>` → `<aside S-R>`，视觉左右由 grid 列位控制，不靠 DOM 顺序。无路由。
- **窄屏约定（<1080px）**：三栏解除为单列，DOM 顺序即视觉顺序（主内容最前）；S-L 折叠为主区上方横向报告条（可横向滚动），S-R 折叠为主区下方面板；主区优先。
- **弹层条款（v2 修订，继续有效）**：全站唯一弹窗 = G10 驳回理由弹窗 S11（用户明确要求窗口输入）。S-R 抽屉**不是弹层/模态**（无遮罩、不圈焦点、收起不影响主区）；补充建议表单等一切确认均为 inline。
- G9 多报告聚合展示不变：默认「全部」，左栏是聚焦器不是切换页。

### 2.1 S1 报告概览头

- 位于主区顶部（G14：统计与通知 chip 保留在主区顶部，不进侧栏）。
- 标题「决策看板」（`.page-title`），副题「报告驱动的行动闭环」（`.overview-lede`）。
- 元信息行（`.overview-meta`）：`最新报告 {文件名} · {MM-DD HH:mm} 导入 · 共 {N} 份报告 · 建议 {a} · 已采纳 {b} · 已驳回 {c}`，后接通知 chip；演示态追加「演示数据」chip（`.demo-chip`，warn 色）。
- 行右端「运行详情」开关钮（plain/ghost 样式）：`aria-expanded={抽屉开}` + `aria-controls` 指向 S-R；打开/关闭抽屉，关闭后焦点回开关钮。G14 后该钮是概览头一部分（v3 前参考实现的独立顶栏不采用——本项目无独立顶栏）。
- **不出现**校准/teach/学习类文案（G12 无用户可见界面，见负面用例 7）。
- 通知 chip 四态（沿用 `.notify-chip`；数据源 = BoardView.notify 的 `configured` / `imConfigured` / `lastPushedReport`，推送集合来自 notify-state）：
  1. 飞书已配置且已推送（`imConfigured` 且 `lastPushedReport` 非空）→ ok 色 `已推送 · {报告名}`
  2. 飞书已配置未推送（`imConfigured` 且无 `lastPushedReport`）→ warn 色 `已配置 · 未推送`
  3. 飞书未配置、webhook 已配置（`configured` 且无 `imConfigured`，文本摘要降级）→ warn 色 `未配置飞书 · 文本摘要推送`
  4. 均未配置（`configured` 为 false）→ warn 色 `推送未配置`
- **禁止**出现旧文案：数据窗口、期次、已累积 N 期、上周行动对照（CSV 管线退役，G1/G2/G5）。

### 2.2 S1b 报告状态条

- 按导入时间倒序（G1）；每项：文件名、导入时间、状态 chip。
- 状态与操作：
  - `待抽取`（queue 色）+「抽取」按钮 → `POST /api/reports/extract`
  - `抽取中`（见 S10）
  - `已抽取`（ok 色）+「重新抽取」两段式按钮：首次点击变为「确认重新抽取」，提示文案 `重新抽取将删除该报告中仍处「建议」状态的行动项；已采纳/已驳回/含任务的行动项保留`（G3），再点执行 `force:true`，失焦或 3 秒未点自动还原
  - `抽取失败`（fail 色）+ 原因摘要（如 `模型调用超时（120s）`）+「重试」按钮（US16）
- 与 S-L 状态点**同源**（G14）：同一报告数据两处呈现——S-L 精简（仅状态点），S1b 完整（状态 + 原因 + 操作按钮）；任何一处触发抽取/重试后两处同步刷新。
- 每份报告只抽取/推送一次（US13）：已推送过的报告不因刷新重复推送，界面无需「已推送」重复标记（推送状态在 S1 通知 chip 汇总）。
- G3 重新抽取的删除重建仅作用于抽取项；人工补充项（`sourceKind=manual`，`reportId` 空）不受任何报告重抽影响（G11）。

### 2.3 S2 行动项卡片

- 沿用卡片骨架（`.conclusion-card` 同款 surface/border/radius/shadow，类名实现为 `.action-card`）；整卡头为 `<button aria-expanded>`，chevron `▸/▾`（沿用现有约定）。
- 卡头内容：
  - chip 行：状态 chip（建议=queue 色 / 已采纳=ok 色 / 已驳回=中性灰，对齐现有 `st-pending/st-accepted/st-rejected` 按下配色）、证据等级 chip（四级色标，见第 6 节）、优先级 chip（高=fail 色 / 中=warn 色 / 低=queue 色，对齐现有 `sev-*` chip）、effort/scene/lifecycle 值 chip（中性，值 = 模型枚举输出原样中文，UI 不翻译不改写；枚举值集合由实现阶段 validator 定义）、所属报告 chip（抽取项 = 报告文件名去扩展名；人工项 = 「人工补充」）。
  - 标题（`.card-title`）+ rationale（`.conclusion-summary` 同款副文本，无前置标签）。
  - 右侧 meta：抽取项 `置信度 {0–100 整数}%`；**人工项**显示中性徽标「人工」（替代置信度数值，不参与派生公式，G11）。置信度必须由证据派生（US3），禁止呈现为模型自评。
- 操作区（卡头下方常显，不依赖展开）：按钮组「采纳」「驳回」（`aria-pressed` 单选语义，`suggested` 态两者均未按下）；已决后显示留痕 `decidedBy · MM-DD HH:mm · 渠道`，渠道 ∈ {看板, 飞书}（US4/US7，沿用 `.decided-meta`）。允许改判（PATCH 语义），留痕随之更新。
- **驳回交互（G10）**：点击「驳回」不直接落库，先开 S11 弹窗，理由确认后才 `dismissed`；改判为驳回同样经弹窗。取消/Esc = 无变更。
- **已驳回卡展开**：证据展开区首块显示「驳回理由」（见 2.13）；看板渠道驳回显示已填理由只读文本；飞书渠道驳回显示默认值 `卡片驳回（未填理由）` + 补填入口（S12）。
- 不提供删除行动项入口（API 的 `DELETE /api/actions/:id` 不设 UI 按钮，保护决策留痕）。

### 2.4 S3 证据展开区

抽取项卡头展开后（`.evidence` 分区，沿用 `.evidence-block` 虚线分区），自上而下：

1. **事实**（facts）：每条 = 事实等级 chip（四级色标）+ 报告原文引用块（`quote-block`：左侧 3px 等级色边 + `--soft` 底，原文逐字，不加引号装饰、不转写）+ 该事实一句话说明。
2. **推导过程**（reasoning）：正文段落。
3. **预期效果**（expectedImpact）：正文段落。
4. **置信度说明**：`置信度由证据派生（证据等级与原文引用决定），非模型自评。`
5. **警示行**（钉死逐字，不可省略）：`证据等级由提取模型自评，未做真实数据重验证`
- facts 为空（validator：无 facts 置信度封顶 0.5）时显示：`未引用报告事实（置信度已按无事实封顶 0.5）`（`.empty-lite`）。
- **禁止**出现：核心指标图、归因明细表、贡献图、任何 ECharts 图表（G2 退役）。

**人工项变体（G11）**：无「事实」块（显示 `.empty-lite`：`人工补充建议，未引用报告事实`）；「推导过程」= 表单「依据」原文；无「预期效果」块（表单无该字段）；第 4/5 条替换为一行说明：`人工补充建议：不参与置信度派生，证据等级固定「经验假设」。`（人工项无模型自评环节，原警示行对其不成立，故以准确说明替代——见发现与复检）。

### 2.5 S4 任务列表与编辑

- 仅 `status=adopted` 的行动项卡内展示（人工项采纳后同权）；区块标题「任务」。
- 任务行：状态三钮（待办/进行/完成，`aria-pressed` 单选，配色：待办=queue、进行=warn、完成=ok）+ 主文本（note，空则「（未填备注）」）+ meta `负责人 {owner} · 截止 {YYYY-MM-DD} · 优先级 {高|中|低}` +「编辑」按钮。
- 「编辑」展开行内表单（与新增表单同构，预填现值），非弹层。
- 新增任务表单字段：标题\*（文本，必填）、负责人（文本，可选）、截止日（date，可选）、优先级（select 高/中/低，默认中）、备注（文本，可选）；按钮「添加任务」「取消」。
- 任务无删除按钮（API 未提供 DELETE /api/tasks/:id）；无任务时 `.empty-lite`：`暂无任务，添加第一个执行任务`。

### 2.6 S5 反馈回录表单

- 每任务一条反馈（PRD schema：一任务一条；API 仅 POST/GET，无 PATCH）：
  - **未回录** → 表单：已执行（checkbox，默认勾选）、结果\*（textarea）、指标变化（文本，placeholder 例 `复购率 +2.3pp`）、复盘（textarea）、评分\*（radio 1–5，组提示 `5=显著正向效果 · 3=无明显变化 · 1=显著负向`，G4）；按钮「提交反馈」。
  - **已回录** → 只读反馈块（`.action-review` 同款虚线区）：`已执行|未执行 · 评分 {n}/5` + 结果/指标变化/复盘各行；一任务一条反馈，已回录可经「更新反馈」按钮展开表单走同端点覆盖，默认只读。
- 提交成功后表单原地替换为只读块。

### 2.7 S7 演示态（G7）

- 触发：无报告（`data/raw/` 为空）。有报告但无密钥 → 走 S9 错误态，**不得**显示演示态（G7：区分「无输入」与「能力故障」）。
- 概览头显示「演示数据」chip（warn，沿用 `.demo-chip`）；通知 chip 显示真实配置状态（演示数据不伪造推送状态）。
- 演示说明条：`当前为演示数据：将分析报告（.md/.txt）放入 data/raw/ 后自动抽取真实行动项。`
- 固定 3 条演示行动项，各覆盖一种证据等级：**数据支撑 / 逻辑推断 / 经验假设**（覆盖「报告原文支撑 → 推导 → 无数据降级」可信度叙事链；多源佐证级仍可见于过滤器与四级图例）。每卡右上角「示例」小标（`--text-3`）。
- 演示行动项可展开、可点击采纳/驳回/任务/反馈表单（形态完整；演示态下「驳回」同样走 S11 弹窗形态），但一切操作仅本地临态、**不落库**（沿用现有 `useActionStore(Boolean(data.period))` 演示不落库先例），说明条已声明。
- 演示态下 S-L 报告列表为空态（见 2.15 空态文案），固定项「全部/人工补充」仍在。

### 2.8 S8 空态

- **报告空态**（有报告、状态=已抽取、行动项 0；抽取 prompt 无行动项返回空数组是合法结果）：`.empty` 卡：标题 `该报告未抽取到行动项`，提示 `报告已解析完成，但未包含可执行建议；可尝试重新抽取或检查报告内容。`
- **过滤空态**：列表区 `.empty-lite`：`该过滤条件下暂无行动项`。
- **无报告**不是空态 → S7 演示态（S-L 空态文案见 2.15）。

### 2.10 S10 加载态

- **单报告抽取中**：S1b 该报告项 chip `抽取中`（queue 色 + CSS 旋转指示；S-L 对应项状态点同步），区块 `aria-live="polite"` 提示：`正在抽取行动项，模型调用最长约 2 分钟，完成后自动刷新。` 其余报告行动项与操作不受阻塞。

### 2.11 S-EXT 飞书审批卡片（外部表面，内容契约）

在飞书客户端渲染，机制（长连接、直审、幂等、留痕、先到先得、过期拒绝）原样保留（PRD）。卡片内容字段钉死：

- 标题：行动项 title；正文：rationale + 证据摘要（top fact 引用原文 + 事实等级 + 置信度）+ 预期效果；按钮：`采纳`（→adopted）/ `驳回`（→dismissed）。
- **驳回保持单键直驳（G10）**：移动端无输入成本，卡片上不出现理由输入框；卡片渠道驳回 `dismissedReason` 落库默认值 `卡片驳回（未填理由）`，看板 S12 补填覆盖。
- 回执文案：成功 `已{采纳|驳回}：{title}`；重复点击（幂等先到先得）`已按首次点击结果处理：{采纳|驳回}`；过期/已处理 `该卡片已处理或已过期，请到看板查看最新状态。`
- 看板侧同步：decidedVia=飞书，卡内留痕显示渠道「飞书」。

### 2.12 S11 驳回理由弹窗（G10，全站唯一弹层）

- **触发**：看板点「驳回」（首次驳回或改判驳回）。
- **实现约定**：原生 `<dialog>` + `showModal()`——原生 Esc 关闭、焦点圈定、`aria-modal` 语义免手写。视觉 = 平面卡片（`--surface` + `--border` + `--r-base` + `--shadow-card`）+ 遮罩 `--scrim`（token 增补，见 6.1）；宽度 `min(420px, 90vw)`。
- **内容**：标题「驳回行动项」+ 所驳回行动项标题（只读引用，`.card-summary`）；`驳回理由 *` textarea + helper `至少 2 个字`；按钮 [确认驳回]（主操作样式）[取消]（普通样式）。
- **校验**：必填 ≥2 字；不足时弹窗内 error（`role="alert"`，fail 色）：`请填写驳回理由（至少 2 个字）`，焦点保持 textarea。
- **焦点管理**：打开 → 聚焦 textarea；确认/取消/Esc 关闭 → 焦点回到触发它的「驳回」钮。提交中两钮 disabled。
- **落库**：确认后 `status=dismissed` + `dismissedReason` + 驳回时间/渠道（看板）；取消 = 无变更、不落库。

### 2.13 S12 补填理由（inline，G10）

- **可见条件**：`status=dismissed` 的行动项，证据展开区首块「驳回理由」：
  - 飞书渠道驳回（理由为默认值）→ 显示 `卡片驳回（未填理由）` + 补填输入（label「补填理由」，单行，≥2 字同校验）+ [保存]；保存成功后原地替换为只读理由文本。
  - 看板渠道驳回 → 显示已填理由只读文本，不再提供覆盖入口（理由是已沉淀的决策资产，防止无限改写；PRD「补充后覆盖」语义限定卡片渠道）。
- 保存失败走 S9 保存失败 alert。
- 飞书卡片本身无输入框（见 2.11）。

### 2.14 S13 补充建议表单与人工补充项（G11）

- **入口**：过滤器区右上「补充建议」主按钮（accent 主操作样式，S6 内唯一主按钮）。
- **表单（区内 inline，非弹窗）**：标题\*（文本）、依据\*（textarea）、场景/周期/优先级/投入（各一枚可选 select，首项「不填」，值集合 = 抽取枚举同一套，由 validator 定义）；按钮 [提交][取消]。
- **提交后**：创建 `sourceKind=manual` 行动项（`reportId` 空），状态=**建议**（仍需采纳确认）；归入过滤器「报告」维「人工补充」分组（S-L 固定项「人工补充」同步聚焦它）；证据等级固定「经验假设」（灰）；卡头 meta 显示中性徽标「人工」替代置信度；报告 chip 为「人工补充」。
- **人工项证据区**：见 2.4 人工项变体（依据原文入推导过程、无事实/预期效果块、固定说明行）。
- 人工项与抽取项同权走 确认 → 任务 → 反馈 闭环（G11）；不受报告重新抽取影响（见 2.2）。
- 表单校验失败（标题/依据为空）：字段下 error `请填写{标题|依据}`；提交失败走 S9。

### 2.15 S-L 左栏报告导航（G13）

- **结构**（固定窄栏 ~240px，`<nav aria-label="报告导航">`）：
  1. 固定项「全部」（默认选中）、「人工补充」；
  2. 报告列表：按导入时间倒序（G1），每项 = 报告名（超长截断省略）+ 导入时间（MM-DD HH:mm）+ 状态点。
- **状态点**（色 + 文字双通道）：待抽取=queue、抽取中=queue+旋转、已抽取=ok、抽取失败=fail；与 S1b 同源（G14），点击左栏项**不带**操作按钮（操作只在 S1b）。
- **点击行为**：报告项 = 主区 S6 过滤器「报告」维聚焦该报告（联动非路由，G9 聚合不变）；「全部」= 清除报告过滤；「人工补充」= 过滤人工项。选中项高亮（对齐 `filter-chip[aria-pressed]` 的 accent-soft 语义），与 S6 报告维 chip 双向同步。
- **无删除入口**：报告是 `data/raw/` 磁盘文件事实源，不在 UI 提供删除（G13）。
- **空态**（无报告，与 S7 演示态并存）：列表区显示 `尚无报告：将 .md/.txt 放入 data/raw/ 后自动出现。`
- 可访问性：nav 项为 `<button aria-pressed>`；窄屏折叠为横向条后同样可 Tab 触达。

### 2.16 S-R 右栏「运行详情」抽屉（G13）

- **开关**：S1 概览头右端「运行详情」按钮（`aria-expanded` + `aria-controls`）；**默认收起**；收起时主区完全不受影响。
- **非模态**：无遮罩、不圈焦点（区别于 S11 弹窗）；关闭（再点开关钮或抽屉头部「关闭」钮）后焦点回开关钮；`<aside aria-label="运行详情">`，头部 = 标题「运行详情」+「关闭」按钮。
- **内容三块**（数据来自 `/api/health` 模型链信息、BudgetStore 快照、审计/日志投影，实现见第 10 节）：
  1. **模型链状态**：主/备模型各一行（角色 + 模型名）+ 密钥 chip（就绪=ok 色 / 未配置=fail 色）。
  2. **任务账本用量**（chips）：`模型调用 {n}` · `token 入 {n}` · `token 出 {n}` · `用时 {n}s`。
  3. **抽取事件时间线**：最新在前；每行 = 时间（HH:mm:ss）· 事件（抽取开始/抽取成功/抽取失败）· 报告名 ·（成功时行动项数 / 失败时原因行，fail 色）。
- **空时间线**：`暂无抽取事件——放入新报告后此处显示。`
- 密钥未配置时模型链行呈 fail chip，与 S9 无密钥错误条同源数据、不同呈现（S-R 常驻详情，S9 任务流内阻断提示）。

## 3. Click paths

### 3.1 主成功路径（US1→US4→US8→US9→US10）

1. **放报告**：用户将 `.md/.txt` 放入 `data/raw/` → S-L 出现新报告项 + S1b 出现状态项（待抽取 → 抽取中，两处同源刷新）→ S10 抽取态 → 自动抽取完成（已抽取，ok）→ S2 列表出现新行动项（状态=建议）；后台按策略推送（高优/高置信逐条飞书卡片，其余文本摘要，US14）。
2. **看证据**：点卡头（或 Enter/Space）→ S3 展开：事实引用块（四级色标）→ 推导过程 → 预期效果 → 置信度说明 → 警示行 → 30 秒内判断（US2）。
3. **确认**：点「采纳」→ 状态 chip 变「已采纳」（ok），留痕 `审批人 · 时间 · 看板` 出现；卡片排序移入已采纳组；S4 任务区出现。点「驳回」→ S11 弹窗填理由（≥2 字）→「确认驳回」→「已驳回」中性 chip + 理由与留痕沉淀。（平行路径：飞书卡片点采纳/驳回 → 看板刷新后同步，渠道=飞书，US5–7；卡片驳回理由为默认值，看板可补填。）
4. **拆任务**：已采纳卡内「添加任务」→ 填负责人/截止日/优先级/备注 → 任务行出现（默认待办）；状态钮 待办→进行→完成（US9）。
5. **回录反馈**：任务下「提交反馈」→ 填已执行/结果/指标变化/复盘/评分 → 表单替换为只读反馈块（US10）。闭环完成。

### 3.2 次级结果路径

- **加载中**：任意写操作（采纳/驳回提交/任务/反馈/补填/补充建议）按钮进入 disabled + 保存中指示；抽取中见 S10。
- **空结果**：报告抽取 0 条 → S8 报告空态；过滤器组合无命中 → S8 过滤空态。
- **部分结果**：多报告聚合下，报告 C 抽取失败（S-L 状态点 fail + S1b 红 + 重试），报告 A/B 行动项照常渲染与操作。
- **演示回退**：无报告 → S7（见 2.7），S-L 列表空态。

### 3.3 显式失败路径

- **抽取失败重试**：S1b `抽取失败：{原因}`（S-R 时间线同现失败原因行）→ 点「重试」→ 回到抽取中 → 成功（行动项出现）或再次失败（保留重试）。临时故障不丢报告（US16）。
- **重新抽取（G3）**：已抽取报告 →「重新抽取」→「确认重新抽取」（两段式 + 删除范围提示）→ force 重抽：仍处「建议」的**抽取项**删除重建，已采纳/已驳回/含任务的保留；人工项不受影响。
- **保存失败**：任一写操作失败（含弹窗确认驳回、补填、补充建议提交）→ 列表底部 `role=alert`「保存失败，已恢复为服务器状态」→ UI 回滚服务器态，可重试操作。
- **飞书不可用降级**：S1 通知 chip `未配置飞书 · 文本摘要推送`（webhook 承接）或 `推送未配置`；看板功能不受影响（推送是旁路，不阻塞闭环）。

### 3.4 变更回灌路径（G10/G11）

- **看板驳回（带理由）**：点「驳回」→ S11 弹窗 → 填理由（≥2 字，不足有 error）→「确认驳回」→ dismissed + 理由留痕；「取消」/Esc → 关闭回驳回钮，无变更。
- **飞书单键驳回 → 补填**：卡片点「驳回」→ 看板该卡 dismissed、理由为 `卡片驳回（未填理由）` → 展开证据区 → S12 补填理由 → [保存] → 理由只读沉淀（覆盖默认值）。
- **人工补充建议**：S6「补充建议」→ S13 表单（标题\*、依据\*）→ 提交 → 人工项出现在「人工补充」分组（状态=建议、「人工」徽标、证据等级「经验假设」）→ 走 3.1-3~5 同权闭环（采纳 → 拆任务 → 回录反馈）。
- G12 校准注入为后端 prompt 行为，无用户可见路径（负面用例 7）。

### 3.5 工作台路径（G13，v3 新增）

- **报告聚焦**：点 S-L 报告项 → S6「报告」维 chip 同步选中、主区列表仅显示该报告行动项（聚合数据不变，视图聚焦）；点「全部」→ 恢复聚合。
- **运行详情**：点 S1「运行详情」→ S-R 抽屉展开（模型链/账本用量/事件时间线）→ 主区滚动与操作不受影响 → 点「关闭」或开关钮 → 收起、焦点回开关钮。抽取进行时打开可在时间线看到 进行中 行。

### 4.2 键盘与焦点顺序

- **DOM 顺序（G13 钉死）**：主内容在前、侧栏在后——`<main>`（S1 开关钮 → S1b 操作钮 → S6 过滤器 + 补充建议 → 卡片流逐卡：卡头 → 采纳/驳回 → 展开区内 驳回理由/补填 → 任务/编辑 → 表单）→ `<aside S-L>`（全部/人工补充/报告项）→ `<aside S-R>`（展开时：关闭钮）。Tab 序即 DOM 序；视觉列位由 grid 控制，不靠 DOM。
- **弹窗焦点圈定（G10）**：S11 打开时焦点困于 dialog 内（原生 `showModal` 提供），Tab 循环不越出；关闭（确认/取消/Esc）后焦点返回触发它的「驳回」钮。
- **S-R 非模态**：抽屉展开不圈焦点、无 Tab 陷阱；键盘用户沿 DOM 自然到达（在 S-L 之后）。
- 全部交互件可 Tab 触达，禁用件 `disabled` 移出焦点；无正 tabindex、无其他焦点陷阱。
- 焦点环统一：`outline: var(--focus-ring); outline-offset: 2px`（3px 半透明橘，tokens.css 契约，所有交互件 `:focus-visible`，含弹窗与抽屉内控件）。

### 4.3 可访问性约束

- 展开态 `aria-expanded` + `aria-controls`；抽取进度区 `aria-live="polite"` + `aria-busy`；错误 `role="alert"`（含弹窗校验 error）。
- 弹窗用原生 `<dialog>`（`aria-modal` 由浏览器提供）；关闭后焦点归还触发钮（2.12）。S-R 为 `aria-label` 标注的 aside（非 dialog）。
- 状态/等级均色 + 文字双通道（chip 内必有文字、状态点带文字，不裸用颜色）；演示/通知 chip 沿用 warn 双通道先例。
- 语义色对（深字 + soft 底 + line 描边）保证对比度；正文 ≥ `--fs-small`。
- `lang="zh-CN"`；表单必填以 `*` + label 标注（评分 radio 组有 legend 说明；弹窗理由有关联 helper 与 error）。
- 窄屏 <1080px：侧栏折叠为横向条/下方面板，DOM 顺序不变（主内容最先），键盘与读屏顺序一致。

## 7. Negative cases（禁止清单）

1. **旧形态禁现**：结论卡、推导链路、核心指标图/贡献图（ECharts）、归因明细表、跨周对照/周趋势、期次与数据窗口文案——全部不出现（G2/G5、PRD Out of Scope）。
2. **演示不冒充真实**：演示态必显「演示数据」chip + 说明条 + 卡角「示例」标；演示操作不落库；无密钥但有报告时显示错误态，严禁以演示态遮掩能力故障（G7）。
3. **证据警示不可省（抽取项）**：抽取项证据展开区必须逐字呈现「证据等级由提取模型自评，未做真实数据重验证」；过滤器区同附。人工项以 2.4 变体说明行替代（等级为规则固定，原句对其不成立）。
4. **弹层唯一例外（v2 修订）**：全站唯一弹窗 = G10 驳回理由弹窗（用户明确要求窗口输入）；S-R 抽屉不是弹层/模态（无遮罩、不圈焦点）；补充建议表单、任务编辑、补填理由、一切确认均为 inline，不得再造第二处弹层/浮层；不发明 PRD 外界面/交互（无报告上传界面、无多审批人、无行动项删除钮、无反馈编辑钮、无路由）。
5. **置信度表述**：只能呈现「由证据派生」口径与数值，禁止「模型自评/模型置信」字样；人工项只显示「人工」徽标，不得伪造百分比。
6. **quote 逐字**：引用块必须逐字呈现报告原文，不摘要、不转写、不加装饰引号。
7. **G12 无用户可见界面（v2 新增）**：抽取校准注入（驳回理由 + 人工补充进 prompt）不产生任何用户可见的界面、标签、状态或说明文案——概览头不加「将用于校准后续抽取」之类句子（PRD 未承诺界面反馈，加了即制造 UI 无法验证的系统性暗示）；「校准/teach/调优/学习」字样不得出现在用户可见文案（5.2）。
8. **飞书卡片无输入框（G10）**：卡片驳回保持单键直驳；理由输入只存在于看板（弹窗/补填），不得把 textarea 塞进卡片。
9. **布局纪律（v3 新增，G13/G14）**：左栏不提供报告删除/重命名入口（报告是磁盘文件事实源）；左栏点击是过滤器聚焦联动，不得做成路由或单报告切换页（G9）；S-R 收起时不得挤占主区或显示残留；S1 统计与通知 chip 不得移入侧栏（G14：保留主区顶部）；不得照抄 reports-factory 的样式/token（只借结构，视觉一律 Xanthil 基线）。
